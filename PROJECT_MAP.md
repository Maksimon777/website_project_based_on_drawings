## Где находятся данные и пароли

**Пароли пользователей не лежат в Python-файлах и не хранятся открытым текстом.** PostgreSQL хранит хеш в поле `password` таблицы `accounts_user`. Django проверяет введённый пароль через check_password. Прочитать исходный пароль из админки нельзя; можно установить новый через админку или команду `manage.py changepassword имя_пользователя`. Не редактируйте хеш вручную.

| Данные | Место хранения |
|---|---|
| Имя, email, Telegram, предпочтение доставки, хеш пароля, права | Таблица `accounts_user` PostgreSQL |
| Заголовок, описание, срок, форматы, статус, исполнитель | Таблица `orders_order` |
| Имя, размер, путь файла, владелец загрузки | Таблица `orders_orderfile` |
| Кто и когда изменил статус, пояснения | Таблица `orders_statushistory` |
| Состояние входа | Серверная таблица `django_session`; в браузере идентификатор сессии |
| База PostgreSQL целиком | Docker volume `chertezhi_postgres_data`, внутри контейнера `/var/lib/postgresql/data` |
| Сами исходные файлы | `media/orders/номер_заказа/случайное_имя.расширение` |
| Ключ Django и пароль подключения к базе | Локальный `.env`, не включённый в Git |
| Образец переменных без секретов | `.env.example` |
| Ошибки во время локальной работы | Терминал Django; LOGGING в settings.py. Постоянный файл журнала пока не подключён |

Каждый участник имеет отдельную локальную базу: push в GitHub не передаёт пользователей, пароли, заказы и файлы. Хранилище Docker сохраняется при обычной остановке; оно не заменяет резервную копию. Команда `docker compose down -v` удаляет volume и данные.

## Как проходит запрос

Браузер отправляет запрос → Django находит обработчик в urls.py → форма проверяет данные → сервис выполняет действие с базой → шаблон HTML показывает результат. CSS отвечает за внешний вид, а не за права доступа.

- **Регистрация:** accounts/urls.py → register → RegistrationForm → User → PostgreSQL. Пароль хешируется UserCreationForm. После создания предлагается войти.
- **Вход:** EmailLoginView → EmailAuthenticationForm → EmailBackend → check_password → сессия Django.
- **Профиль:** profile работает только с request.user; перед сменой email проверяет текущий пароль.
- **Заказ:** editor → OrderForm → save_customer_order → Order + OrderFile + StatusHistory. Вложения сохраняются на диск по частям.
- **Обработка:** OrderAdmin → ProcessingForm → update_by_staff. Статус и запись истории сохраняются одной транзакцией.
- **Скачивание:** download сначала проверяет доступ и только потом открывает файл. Выдача идёт вложением для скачивания, без исполнения в браузере.

## Правила заказов

Категории пока две: **Начертательная геометрия**, **Другое**. Обязательны название, категория, описание, срок и хотя бы один формат результата. Требования преподавателя и исходные файлы необязательны. Если выбран формат «Другое», нужно пояснение. Срок может быть сегодняшним или будущим.

| Статус | Клиент редактирует | Что дальше |
|---|---|---|
| Отправлен | Да | Администратор принимает в обработку либо отменяет |
| Принят в обработку | Нет | Возврат на уточнение, назначение и выполнение либо отмена |
| Нужно уточнение | Да | Клиент дополняет и отправляет заново; статус снова «Отправлен» |
| На выполнении | Нет | Готов, нужно уточнение либо отмена |
| Готов | Нет | Завершён либо возврат на выполнение |
| Завершён | Нет | Конечный статус |
| Отменён | Нет | Конечный статус |

Клиент отменяет только при «Отправлен» или «Нужно уточнение». Администратору для возврата на уточнение нужно заполнить поле «Что нужно уточнить». Для начала выполнения обязателен активный сотрудник-исполнитель.

**Важно для админа:** простое открытие карточки не блокирует редактирование. Выберите «Принят в обработку» и нажмите «Сохранить». Так статус не меняется из-за случайного открытия ссылки. При устаревшей форме система попросит обновить страницу.

revision — номер изменения заказа. select_for_update — блокировка строки базы на время записи: клиент и администратор не могут одновременно незаметно перезаписать заказ.

## Как редактировать самостоятельно

1. Откройте нужный файл через список слева или Ctrl+P и его имя.
2. Тексты и кнопки меняйте в HTML. Сохраните Ctrl+S и обновите браузер. После CSS при необходимости нажмите Ctrl+F5.
3. Не удаляйте `{% csrf_token %}`, проверки пользователя и конструкцию `{% url ... %}`: они отвечают за защиту и адреса.
4. Python после изменения нужно перезапустить, если сервер был запущен с `--noreload`. Обычный запуск по F5 отслеживает изменения.
5. Если меняете модели/категории со choices, создайте новую миграцию и примените её; старые применённые миграции не переписывайте.
6. После изменения логики выполните тесты и обновите этот документ.

Например, в Order.Category можно добавить строку с новым постоянным кодом и русским названием. Существующие коды `geometry`, `other` не переименовывайте без переноса данных. В Order.OUTPUT_FORMATS добавляются пары «код, название»; ранее сохранённые заказы используют именно коды.

Команды в терминале корня проекта:

```powershell
.\.venv\Scripts\python.exe manage.py makemigrations
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test
.\.venv\Scripts\python.exe scripts/check_project_map.py
```

| `.env` | Локальные реальные настройки и секреты; не публиковать |
| `.venv/pyvenv.cfg` | Путь к базовому Python и параметры окружения |
| `.venv/.gitignore` (если создан инструментом окружения) | Дополнительное исключение зависимостей из Git |
| `__pycache__/*.pyc` | Скомпилированный кеш Python; вручную не менять |
| `media/orders/*/*` | Содержимое исходных файлов клиентов; имена случайные |
| Временные *.upload в системной временной папке Windows | Промежуточные загрузки Django до сохранения |
| *.log (если создаются локальными инструментами) | Диагностические записи, исключены из Git; сервер сейчас пишет в терминал |

## Что уже работает и что ещё предстоит

Работают аккаунты, профиль, список и карточка заказов, редактирование по статусу, исходные файлы, защищённое скачивание, админская обработка, назначение исполнителя и история.

Пока нет переписки, загрузки готовых результатов, автоматической отправки email/Telegram, восстановления пароля, подтверждения email, платежей и публичного размещения. Статус «Готов» сам по себе не отправляет документ клиенту. Telegram в профиле — сохранённый контакт, а не подключённый бот.

Проверка файлов ограничена расширениями и базовыми сигнатурами, а не антивирусом. ZIP/DOCX не распаковываются. Для КОМПАС не выполняется полноценный разбор формата. Безлимитный размер согласован для локального тестирования; место на диске и время загрузки остаются ограниченными. При сбое очистки незавершённых файлов журнал сообщает об ошибке; аварийное выключение компьютера может потребовать отдельной уборки временных данных.
