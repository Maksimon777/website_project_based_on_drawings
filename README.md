# Сервис заказов на чертежи

Начальный каркас проекта команды. Django работает локально, PostgreSQL — в Docker. Сейчас доступны заглушка главной страницы, проверка базы и стандартная административная панель. Регистрация, заказы, сообщения и загрузка файлов ещё не реализованы.

## Инструменты

- Python 3.13, Git, VS Code с расширением Python.
- Docker Desktop с запущенным движком Linux-контейнеров.
- Зависимости Python зафиксированы в `requirements.txt`.
- Образ PostgreSQL 17 закреплён по SHA256 в `compose.yaml`; обновления выполняются командой осознанно с проверкой миграций и резервной копией.

Откройте в VS Code именно папку репозитория с `manage.py`. Все команды ниже выполняются в её терминале PowerShell. Каждая команда должна завершиться успешно перед следующей. Первая загрузка образа PostgreSQL требует доступа к Docker Hub.

## Первый запуск на новом компьютере

1. Создайте окружение через **Ctrl+Shift+P → Python: Create Environment → Venv → Python 3.13**. Выберите его через **Python: Select Interpreter**. Если `.venv` уже существует, повторно создавать его не нужно.
2. Установите зависимости:

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

3. Создайте локальные настройки со случайными ключом и паролем:

   ```powershell
   .\.venv\Scripts\python.exe scripts/init_env.py
   ```

   Скрипт не заменяет существующий `.env`. Не отправляйте этот файл в Git или чат. `.env.example` содержит только пример без настоящих секретов.

4. Откройте Docker Desktop, дождитесь **Engine running**, затем запустите базу:

   ```powershell
   docker compose up -d --wait
   ```

   Если `docker` не найден, полностью перезапустите VS Code после установки Docker Desktop. В вашей установке доступен также запуск по полному пути:

   ```powershell
   & "$env:LOCALAPPDATA\Programs\DockerDesktop\resources\bin\docker.exe" compose up -d --wait
   ```

5. Создайте таблицы:

   ```powershell
   .\.venv\Scripts\python.exe manage.py migrate
   ```

6. Если нужен доступ в административную панель, создайте личного администратора (пароль при вводе не отображается):

   ```powershell
   .\.venv\Scripts\python.exe manage.py createsuperuser
   ```

7. Запустите сайт через **F5 → Django: локальный сайт** или командой:

   ```powershell
   .\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
   ```

8. Откройте в браузере:
   - http://127.0.0.1:8000/ — стартовая страница.
   - http://127.0.0.1:8000/health/ — ожидается `{"status": "ok", "database": "ok"}`.
   - http://127.0.0.1:8000/admin/ — вход администратора по имени пользователя.

## Повторный запуск и остановка

Откройте Docker Desktop, выполните `docker compose up -d --wait`, затем запустите Django через F5. Остановка Django: Shift+F5 при отладке или Ctrl+C в терминале. Остановка базы: `docker compose stop`.

Каждый участник имеет собственную локальную базу. Docker volume сохраняет данные при обычной остановке и пересоздании контейнера. Команда `docker compose down -v` удаляет данные — не используйте её для обычной остановки. Volume не заменяет резервную копию.

## Структура

| Путь | Назначение |
|---|---|
| `config/` | Настройки Django и маршруты |
| `accounts/` | Модель пользователя и будущие профили/авторизация |
| `orders/` | Каркас будущего модуля заказов |
| `core/` | Главная страница, проверка базы, тесты |
| `templates/` | HTML |
| `static/` | CSS и будущие статические ресурсы |
| `media/` | Будущие пользовательские файлы, вне Git |
| `compose.yaml` | PostgreSQL и постоянный volume |
| `scripts/init_env.py` | Создание локальных настроек |

Используется собственная модель пользователя на основе стандартной Django: это позволит расширять её без поздней замены таблицы пользователей. Вход по email будет реализован на этапе авторизации. Приложение не публикует `media/` напрямую: выдача файлов потребует проверки владельца заказа.

## Проверки

При работающей базе выполните:

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test
```

Тесты проверяют реальное соединение с PostgreSQL, ответ 503 при недоступной базе без раскрытия деталей и открытие главной страницы. Django создаёт и удаляет отдельную тестовую БД; рабочая база не очищается.

## Если возникла ошибка

- **Порт 5432 занят:** поменяйте `POSTGRES_PORT` в `.env`, например на `5433`, и повторите запуск базы. Django использует то же значение.
- **База недоступна:** проверьте Docker Desktop и `docker compose ps`. `/health/` вернёт 503; журнал в терминале покажет тип ошибки без пароля.
- **Не подходит пароль базы:** переменные `POSTGRES_*` инициализируют только новый volume. Изменение `.env` не меняет пароль уже созданной базы. Не удаляйте volume с нужными данными; согласуйте изменение пароля.
- **Ошибка скачивания зависимостей/образа:** сохраните текст ошибки. При 403 проверьте доступ к соответствующему сервису; установка не считается завершённой.

Эти настройки предназначены для локальной разработки: сервер и база слушают только этот компьютер, почта выводится в терминал, журнал ошибок тоже находится в терминале. Перед публикацией потребуются отдельные настройки HTTPS, хранения файлов, логов, почты и резервных копий. Пока нет формы загрузки файлов; будущие загрузки настроены на запись временных файлов на диск вместо хранения целиком в RAM. Лимиты размера и время ожидания сервера нужно согласовать перед публичным запуском.
