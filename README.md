# Сервис заказов на чертежи

Проект команды: Django работает локально, PostgreSQL — в Docker. Доступны регистрация, профиль, создание и редактирование заказов, загрузка исходных файлов и обработка в админке. Выдача готовых файлов, переписка и автоматическая отправка ещё не реализованы.

**Где что редактировать:** [PROJECT_MAP.md](PROJECT_MAP.md) описывает каждый собственный файл и папку проекта, кнопки, функции и хранение данных. Карта обновляется вместе с проектом; правило закреплено в [AGENTS.md](AGENTS.md).

## Инструменты

- Python 3.13, Git, VS Code с расширением Python.
- Docker Desktop с запущенным движком Linux-контейнеров.
- Зависимости Python зафиксированы в `requirements.txt`.
- Образ PostgreSQL 17 закреплён по SHA256 в `compose.yaml`; обновления выполняются командой осознанно с проверкой миграций и резервной копией.

Откройте в VS Code именно папку репозитория с `manage.py`. Все команды ниже выполняются в её терминале PowerShell. Каждая команда должна завершиться успешно перед следующей. Первая загрузка образа PostgreSQL требует доступа к Docker Hub.

## Первый запуск на новом компьютере

1. Создайте окружение через **Ctrl+Shift+P → Python: Create Environment → Venv → Python 3.13**. Выберите его через **Python: Select Interpreter**. Если `.venv` уже существует, повторно создавать его не нужно.
2. Установите зависимости:

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

3. Создайте локальные настройки со случайными ключом и паролем:

   ```powershell
   .\.venv\Scripts\python.exe scripts/init_env.py
   ```

   Скрипт не заменяет существующий `.env`. Не отправляйте этот файл в Git или чат. `.env.example` содержит только пример без настоящих секретов.

4. Откройте Docker Desktop, дождитесь **Engine running**, затем запустите базу:

   ```powershell
   docker compose up -d --wait
   ```

   Если `docker` не найден, полностью перезапустите VS Code после установки Docker Desktop. В вашей установке доступен также запуск по полному пути:

   ```powershell
   & "$env:LOCALAPPDATA\Programs\DockerDesktop\resources\bin\docker.exe" compose up -d --wait
   ```

5. Создайте таблицы:

   ```powershell
   .\.venv\Scripts\python.exe manage.py migrate
   ```

6. Если нужен доступ в административную панель, создайте личного администратора (пароль при вводе не отображается):

   ```powershell
   .\.venv\Scripts\python.exe manage.py createsuperuser
   ```

7. Запустите сайт через **F5 → Django: локальный сайт** или командой:

   ```powershell
   .\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
   ```

8. Откройте в браузере:
   - http://127.0.0.1:8000/ — стартовая страница.
   - http://127.0.0.1:8000/health/ — ожидается `{"status": "ok", "database": "ok"}`.
   - http://127.0.0.1:8000/admin/ — вход администратора по имени пользователя.

## Повторный запуск и остановка

Откройте Docker Desktop, выполните `docker compose up -d --wait`, затем запустите Django через F5. Остановка Django: Shift+F5 при отладке или Ctrl+C в терминале. Остановка базы: `docker compose stop`.

Каждый участник имеет собственную локальную базу. Docker volume сохраняет данные при обычной остановке и пересоздании контейнера. Команда `docker compose down -v` удаляет данные — не используйте её для обычной остановки. Volume не заменяет резервную копию.

## Структура

| Путь | Назначение |
|---|---|
| `config/` | Настройки Django и маршруты |
| `accounts/` | Модель пользователя и будущие профили/авторизация |
| `orders/` | Заказы, статусы, файлы, формы и обработка в админке |
| `core/` | Главная страница, проверка базы, тесты |
| `templates/` | HTML |
| `static/` | CSS и будущие статические ресурсы |
| `media/` | Исходные файлы заказов, вне Git |
| `compose.yaml` | PostgreSQL и постоянный volume |
| `scripts/init_env.py` | Создание локальных настроек |

Используется собственная модель пользователя на основе стандартной Django. Клиенты входят по email, административная панель сохраняет вход по имени пользователя. Файлы выдаются отдельным защищённым маршрутом: владелец заказа или активный сотрудник с правом просмотра заказов. Прямой публикации `media/` нет.

## Заказы

1. Клиент открывает «Мои заказы» → «Создать заказ», заполняет обязательные поля и при необходимости выбирает несколько файлов.
2. Категории: «Начертательная геометрия» и «Другое». Можно выбрать несколько форматов результата: PDF, КОМПАС, DWG/DXF, изображение, подготовка к печати, работа от руки, другое.
3. До принятия в обработку клиент может редактировать заказ и добавлять файлы. Существующие файлы сохраняются. Удаление и замена отдельных вложений пока не реализованы.
4. Администратор открывает `/admin/orders/order/`, выбирает заказ, устанавливает «Принят в обработку» и сохраняет. С этого момента редактирование клиентом закрыто. Открытие страницы само по себе статус не меняет.
5. Для возврата клиенту выбрать «Нужно уточнение» и обязательно заполнить пояснение. После исправления клиент нажимает «Сохранить и отправить», статус снова становится «Отправлен».
6. Перед переводом в «На выполнении» нужно назначить активного сотрудника. Далее доступны «Готов» и «Завершён». Это пока статусы: прикладывание готовых результатов будет следующим этапом.
7. Отмена клиентом доступна только до принятия в обработку или при возврате на уточнение. История статусов сохраняется.

Исходные файлы: PDF, JPG/JPEG, PNG, DOCX, ZIP, DWG, DXF, CDW, FRW, M3D, A3D, SPW. Выполняется проверка расширений и базовых заголовков для распространённых форматов; это не антивирус и не полная проверка CAD-документа. Архивы не распаковываются. Размер одного файла пока не ограничен приложением; остаются пределы свободного диска и времени загрузки. Если хотя бы один файл не прошёл проверку, заказ не сохраняется. При ошибке записи выполняется откат базы и удаление новых файлов; если само хранилище недоступно, ошибка очистки записывается в журнал.

Для просмотра и обработки заказов сотруднику нужны права `orders.view_order` и `orders.change_order` и отметка «Статус персонала». Выдавайте их в админке пользователей. У суперпользователя права уже есть.

## Регистрация и профиль

- `/accounts/register/` — имя, обязательный email и пароль с повторным вводом. Подтверждение адреса письмом пока отключено.
- `/accounts/login/` — вход по email и паролю; регистр букв в email не влияет на вход.
- `/accounts/profile/` — редактирование имени, email, Telegram и способа получения результата. Для смены email требуется текущий пароль; последующий вход выполняется по новому адресу.
- Telegram вводится как `@username`. Если выбран способ получения через Telegram, это поле обязательно.
- Повторный email запрещён формой и индексом PostgreSQL, в том числе при одновременных запросах.
- Выход выполняется кнопкой «Выйти» через защищённый POST-запрос. Формы используют CSRF-защиту.
- Способ получения — пока только предпочтение пользователя. Автоматическая отправка файлов, подтверждение контактов и восстановление пароля будут отдельными этапами.

После получения обновлений остановите локальный Django, выполните `manage.py migrate` через Python из `.venv` и снова запустите сервер. Перед публичным запуском также потребуется ограничение частоты попыток входа и регистрации.

## Проверки

При работающей базе выполните:

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test
.\.venv\Scripts\python.exe scripts/check_project_map.py
```

Тесты проверяют базу, авторизацию, закрытый профиль, создание и изменение заказов, недопустимые переходы статусов, устаревшие формы, загрузку нескольких файлов, откат при ошибках и запрет чужих скачиваний. Django создаёт и удаляет отдельную тестовую БД; тестовые файлы записываются во временную папку, рабочие данные не очищаются.

## Если возникла ошибка

- **Порт 5432 занят:** поменяйте `POSTGRES_PORT` в `.env`, например на `5433`, и повторите запуск базы. Django использует то же значение.
- **База недоступна:** проверьте Docker Desktop и `docker compose ps`. `/health/` вернёт 503; журнал в терминале покажет тип ошибки без пароля.
- **Не подходит пароль базы:** переменные `POSTGRES_*` инициализируют только новый volume. Изменение `.env` не меняет пароль уже созданной базы. Не удаляйте volume с нужными данными; согласуйте изменение пароля.
- **Ошибка скачивания зависимостей/образа:** сохраните текст ошибки. При 403 проверьте доступ к соответствующему сервису; установка не считается завершённой.

Эти настройки предназначены для локальной разработки: сервер и база слушают только этот компьютер, почта выводится в терминал, журнал ошибок тоже находится в терминале. Перед публикацией потребуются отдельные настройки HTTPS, хранения файлов, логов, почты и резервных копий. Загрузки записываются на диск, а не целиком в RAM. Лимиты размера и время ожидания сервера нужно согласовать перед публичным запуском.
